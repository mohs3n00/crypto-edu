## 3. Detailed Syllabus Mapping Matrix

### Unit 1: Foundations, Perspectives & Organizational Context (`bpm-ch1`)
- **Lesson 1.1: Foundations & Evolution of Process Thinking (`bpm-ch1-l1`):**
  - Adam Smith (1776) *Wealth of Nations* pin factory division of labor vs modern process integration.
  - Functional silo effect: fragmentation, handoffs, communication gaps, and customer blindness.
  - Rummler & Brache 3 levels of performance: Organizational, Process, and Activity/Job levels.
  - Cross-functional alignment and customer value delivery.
- **Lesson 1.2: Enterprise Case Study: Canon HR Digitization (`bpm-ch1-l2`):**
  - Canon HR operations pre-transformation: 100+ decentralized forms, paper-based routing, opaque approvals.
  - Solution architecture: Unified portal, digital form standardization, automated routing.
  - Quantified empirical metrics: **15% reduction in overall processing time**, zero lost documents, 100% auditable SLA compliance.
  - 3-tier model: Strategic HR governance, Process orchestration layer, Employee self-service interface.
- **Lesson 1.3: The Business Process Concept & Core Dimensions (`bpm-ch1-l3`):**
  - Academic definitions (Weske, Davenport, Hammer & Champy).
  - 5 core elements: Input, Output, Activities/Tasks, Resources/Actors, Value Proposition.
  - Critical distinction: **Process** (repetitive, ongoing, standardized value stream) vs **Project** (temporary, unique, defined deadline).
  - Core, Support, and Management process classifications.
- **Lesson 1.4: Models & Abstraction Theory (`bpm-ch1-l4`):**
  - Herbert Stachowiak (1973) General Model Theory:
    1. *Mapping Feature (Abbildungsmerkmal):* Represents an original entity.
    2. *Reduction Feature (Verkürzungsmerkmal):* Omits non-relevant attributes.
    3. *Pragmatic Feature (Pragmatisches Merkmal):* Built for specific users, periods, and purposes.
  - Metaphorical perspectives: Kitchen metaphor (chef, recipe, ingredients) and Airbus manufacturing metaphor (thousands of suppliers coordinated as end-to-end stream).

### Unit 2: Management Systems, Lifecycles & Governance (`bpm-ch2`)
- **Lesson 2.1: Process-Aware Information Systems (PAIS) & BPMS (`bpm-ch2-l2`):**
  - Definition of PAIS: Separation of process control logic from application software code.
  - 4 core components of a BPMS:
    1. *Process Modeling Tool:* Graphical design interface for business analysts.
    2. *Workflow Engine (Enactment Service):* Orchestrates execution, evaluates state transitions.
    3. *Worklist Handler:* Delivers human tasks to users' work queues.
    4. *Administration & Monitoring Tools:* Real-time dashboards, BAM, SLA tracking.
- **Lesson 2.2: Process Lifecycles: Circular & Spiral Models (`bpm-ch2-l2`):**
  - Weske circular lifecycle: Design & Analysis → Configuration → Enactment → Evaluation.
  - 6-phase enterprise lifecycle: Process Identification → Process Discovery → Process Analysis → Process Redesign → Process Implementation → Process Monitoring & Controlling.
  - Circular vs Spiral model: Spiral incorporates iterative prototyping, evolutionary feedback, and continuous risk assessment.
- **Lesson 2.3: Process Taxonomies & Case Analysis (`bpm-ch2-l3`):**
  - Continuous vs Ad Hoc processes.
  - Simple vs Complex processes.
  - Case study: IT Support Service Desk (Tier 1 triage, Tier 2 specialized resolution, Tier 3 vendor escalation with timer-driven SLA auto-escalation).
- **Lesson 2.4: Process Governance & Standards Spectrum (`bpm-ch2-l4`):**
  - The Process Owner role: End-to-end accountability, cross-departmental coordination, continuous KPI optimization.
  - Standards landscape: Modeling languages (EPC, BPMN, UML Activity Diagrams), Execution languages (WS-BPEL), Reference models (WfMC, SCOR).

### Unit 3: BPMN 2.0 Syntax, Gateways & Workflow Patterns (`bpm-ch3`)
- **Lesson 3.1: BPMN 2.0 Syntax & Semantic Foundations (`bpm-ch3-l1`):**
  - Official OMG BPMN 2.0 standard history and goals.
  - 4 basic element categories: Flow Objects, Connecting Objects, Swimlanes, Artifacts.
  - Event types: Start (thin border), Intermediate (double border), End (thick border), Boundary Timer events.
  - Activities: User task, Service task, Manual task, Sub-process (expanded vs collapsed).
- **Lesson 3.2: Decision Gateways & Branching Logic (`bpm-ch3-l2`):**
  - Exclusive Gateway (XOR): Marker diamond with 'X' or blank; exactly one path chosen.
  - Parallel Gateway (AND): Marker diamond with '+'; fork initiates concurrent flows, join synchronizes all branches.
  - Inclusive Gateway (OR): Marker diamond with 'O'; one or more paths taken based on independent conditions; join synchronizes all active incoming branches.
  - Complex Gateway (Asterisk '*'): 2-of-3 join, Discriminator execution.
- **Lesson 3.3: Swimlanes, Communication & Boundary Rules (`bpm-ch3-l3`):**
  - Pools: Represent independent participants/organizations.
  - Lanes: Sub-partitions within a pool representing internal roles, departments, or systems.
  - Golden Boundary Rule: **Sequence Flow NEVER crosses Pool boundaries; only Message Flow (dashed line with open circle) connects separate pools.**
  - Sequence Flow crosses Lanes freely within the same pool.
- **Lesson 3.4: Workflow Control-Flow Patterns (`bpm-ch3-l4`):**
  - Van der Aalst workflow patterns:
    1. *Basic Control Patterns:* Sequence, Parallel Split, Synchronization, Exclusive Choice, Simple Merge.
    2. *Advanced Branching Patterns:* Multi-Choice (OR-split), Synchronizing Merge, Discriminator (first token triggers output, subsequent tokens absorbed), N-out-of-M Join.
    3. *Structural Patterns:* Arbitrary Cycles, Implicit Termination.
  - Why BPMN diagrams cannot execute without a workflow engine.

### Unit 4: Workflow Architectures & Management Tools (`bpm-ch4`)
- **Lesson 4.1: The 5-Step Workflow Design Methodology (`bpm-ch4-l1`):**
  - Step 1: Identify Goals & Requirements.
  - Step 2: Map the "as-is" Process (spot bottlenecks, consult frontline staff).
  - Step 3: Identify Areas to Improve (eliminate waste, streamline handoffs).
  - Step 4: Design the "to-be" Process (draft improved model, pilot test).
  - Step 5: Implement, Monitor & Optimize.
  - Performance metrics: Cost vs Cycle Time vs Quality vs Flexibility.
- **Lesson 4.2: Workflow Management Systems Architecture (`bpm-ch4-l2`):**
  - Workflow Engine core mechanics: Process definition repository, active instance state machine, worklist manager, external invocation proxies.
  - Architectural decoupling: Keeping modeling tools separate from runtime engines so business users model without writing code.
- **Lesson 4.3: WfMC Reference Model & Cross-Organizational Choreography (`bpm-ch4-l3`):**
  - Exactly 5 standard interfaces around Workflow Enactment Service:
    - *Interface 1:* Process Definition Import/Export (XPDL/BPMN).
    - *Interface 2:* Workflow Client Applications (Worklists).
    - *Interface 3:* Invoked Applications (External software execution).
    - *Interface 4:* Interoperability (Engine-to-Engine collaboration).
    - *Interface 5:* Administration & Monitoring Tools.
  - Workflow API (WAPI) standard bridge.
  - Weske Multi-Party Collaboration (Reseller, Buyer, Manufacturer Choreography).
- **Lesson 4.4: Strategic Business Management Tools & Frameworks (`bpm-ch4-l4`):**
  - *Lean Thinking:* Eliminating 8 types of waste (muda), value stream focus.
  - *Six Sigma:* DMAIC roadmap, reducing process defects to <3.4 DPMO, eliminating variation.
  - *Kanban Boards:* Visualizing WIP limits (To Do, In Progress, Done).
  - *Gantt Charts:* Project milestone schedules and dependency tracking.
  - *Mind Mapping:* Brainstorming, root-cause tree expansion.
  - *SWOT Analysis:* Internal (Strengths/Weaknesses) vs External (Opportunities/Threats).
  - *Fishbone (Ishikawa) Diagram:* Categorized root-cause analysis (6M: Man, Machine, Method, Material, Measurement, Mother Nature).
  - *Value Stream Mapping (VSM):* Mapping value-adding vs non-value-adding cycle times.
  - *Balanced Scorecard (BSC):* 4 perspectives (Financial, Customer, Internal Process, Learning & Growth).
  - *Software Tools vs Methods distinction:* Trello and Jira are software tools supporting methods like Scrum and Kanban, not the methods themselves.
